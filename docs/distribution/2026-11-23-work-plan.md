# Presentation Director 首轮产品化工作计划

- 日期：2026-11-23
- 依据：`2026-11-23-engine-plan-review-brief.md` 第 7 节（审查结论处理）
- 首轮目标：首位试用者从 NECTO 官网下载安装包，在自己的 WorkBuddy 里接入，不装 Codex、不找源码、不敲命令；提供一份中文资料、点确认，拿到一份能继续编辑的 `.pptx`，并能改一处文字、一个表格单元格和一项图表数据。

## 0. 已核实的试用环境（2026-11-23 远程只读查看）

| 项 | 实际情况 | 对计划的影响 |
|---|---|---|
| 系统 | Windows 11 专业版 10.0.26200，64 位 | 首轮只做 Windows x64 安装包 |
| WorkBuddy | 5.11.3 | 按这个版本验收 |
| Office | **WPS Office 12.1**，没有 Microsoft PowerPoint | 「可编辑」验收在 WPS 里做；生成器必须兼容 WPS 的图表数据编辑 |
| MCP 接入 | WorkBuddy 官方连接器市场里有 22 个本机进程（stdio）连接器，格式为 `mcpServers.<名>.type = "stdio"` + `command` + `args` | 本机引擎走 stdio 接入成立 |
| 运行时 | WorkBuddy 自带 Node 22.22.2；Python 目录存在但未装；系统无 Python（只有应用商店占位）、无 LibreOffice | 安装包自带 Python 与 Node，不依赖 WorkBuddy 或系统 |
| 自定义连接器存放位置 | 用户目录下没有第三方教程说的 `.workbuddy-ai\mcp.json`，配置目录是 `.workbuddy\` | 需要实测：在界面里加一次自定义连接器，看写到哪里（见 W5） |

开发机（owner 的 Mac）有 PowerPoint、Keynote，没有 LibreOffice。

## 1. 结构（不变）

```text
Windows 安装包（按用户安装，不需管理员）
  └─ %LOCALAPPDATA%\PresentationDirector\
       ├─ python\        自带 Python（官方嵌入版）+ 预装依赖
       ├─ node\          自带 Node + 固定版本 pptxgenjs
       ├─ engine\        引擎代码（复用 presentation_director.py 的问询/确认页/守卫）
       └─ notices\       LICENSE 与第三方声明
WorkBuddy
  ├─ 连接器：stdio 启动 engine 的 MCP 服务
  └─ 技能：一份短说明，告诉模型何时调用、按什么顺序调用
LibreOffice（官方安装包，由安装包引导安装）：渲染检查用
```

## 2. 工作包

### W1 逐页输入格式（deck-spec v1）
- 新建一份最小 JSON 格式，由宿主模型在用户确认方向后按资料写出，引擎读取：
  - 整体：标题、语言、页数、所选视觉方向
  - 每页：版式、标题、要点、讲稿备注；可选「图表」（类型、分类、系列数据）、「表格」（表头、行）
- 不复用 BPS 治理用的 `PresentationDirectorPlanV1`（它要求治理绑定，对外部宿主太重）；该合同保持不动。
- 交付：`schemas/deck-spec-v1.schema.json` + 一份中文样例（项目周报，含一张柱状图和一个小表格）。
- 通过：样例通过校验；故意写错的样例被拒并给出可读错误。

### W2 PPTX 生成器
- Node + pptxgenjs（固定版本），首轮 6 种版式：封面、要点、左右两栏、图表、表格、结论/待决事项。
- 视觉取自已有 `design-locks/` 与内置视觉候选（`build_visual_candidates`）；字体用 Windows 与 WPS 都有的中文字体，Mac 开发时同名替代。
- 图表用 pptxgenjs 原生图表（带内嵌数据表），表格用原生表格。
- 输出到 `Decks/<任务>/vN/final.pptx`，沿用现有版本目录。
- 通过：样例生成的文件在 WPS（试用机）和 PowerPoint（Mac）都能打开；能改文字、表格单元格、图表数据并保存。**WPS 编辑图表数据是首要风险，第一个出图后就先上试用机验证。**

### W3 渲染与结构检查（A + D 级）
- A：LibreOffice 无界面模式把 PPTX 转 PDF，再用 pypdfium2（宽松许可）逐页转 PNG，Pillow 拼总览图。不用 poppler，少一个依赖。
- D：用 python-pptx 解析文件，检查越出页面、文字估算溢出、空占位、缺字体。
- 检查报告写在同一个 `vN/` 目录；`export` 只交出报告通过的那一版。
- 通过：页数 = 图片数；故意做一页文字溢出的样例被 D 级查出。

### W4 引擎 MCP 服务
- 用官方 MCP Python SDK，stdio 通道，6 个工具：`start_task`、`open_confirmation`、`get_status`、`generate`、`render_check`、`export`。
- 确认页的本机网页服务放在引擎进程里的后台线程，随引擎进程启停。这样 Windows 上不需要另起脱离会话的进程，原先 `start_new_session=True` 的问题自然消失。
- `generate` 内部调用现有 `validate_generation_guard`，命令行入口与 MCP 共用这一个生成入口。
- 把 Codex 专用的生成提示文字移到 Codex 适配层，不动其他函数。
- 通过：用命令行跑通「开始 → 确认页（手动点）→ 生成 → 检查 → 导出」；未确认时 `generate` 被拒。

### W5 WorkBuddy 接入
- 先弄清自定义连接器存在哪里：请试用者在 WorkBuddy「连接器 → 自定义连接器」里随便加一个，我远程看写入的文件。
  - 能找到文件：安装包自动写入连接器配置，用户只需在 WorkBuddy 里点一次「信任」。
  - 找不到：说明页给一段复制即粘的配置（这是首轮唯一允许的「粘贴」操作）。
- 技能包：一个 ZIP，内含简短 `SKILL.md`（何时调用、调用顺序、等待确认时告诉用户去点确认页），按 WorkBuddy「上传技能」导入。
- 通过：在试用机上，WorkBuddy 能列出 6 个工具，模型能按顺序调用到确认页打开。

### W6 Windows 安装包
- 用 Inno Setup 做 `.exe`，按用户安装到 `%LOCALAPPDATA%`，不需要管理员。
- 内含：Python 嵌入版（构建时装好依赖，不在用户机上 pip）、Node、引擎、技能 ZIP、许可与第三方声明。
- LibreOffice：安装包检测，没有就打开官方下载页或下载官方安装包并启动安装（会有一次系统确认）；不镜像、不改包。
- 首轮不做代码签名：Windows 会提示「已保护你的电脑」，说明页写明点「更多信息 → 仍要运行」。
- 自检：安装末尾跑一次引擎自检（生成 + 渲染一页样例），结果写日志。
- 通过：我先在试用机上远程静默安装并跑自检；路径含空格和中文时也能渲染。

### W7 官网测试入口
- nectohq.com 上加一个不公开的测试下载地址（只给试用者），附一页图文说明：下载 → 安装 → WorkBuddy 导入技能、信任连接器 → 发一句话 → 点确认 → 打开成品。
- 附公开样例资料（虚构项目周报）和样例成品。
- 正式下载按钮放到首轮验收通过之后。

### W8 验收
1. 我远程：安装、自检、命令行全流程、渲染图检查。
2. 试用者在桌前，只看说明页：从测试入口下载到打开成品，中途隔几分钟再点确认；在 WPS 里改一处文字、一个表格单元格、一项图表数据。
3. 记录：从下载到打开成品的耗时、每次需要我们介入的地方。
4. 通过后再做 W7 的正式下载按钮。

## 3. 顺序与检查点

| 顺序 | 内容 | 检查点 |
|---|---|---|
| 1 | W1 + W2（Mac 上） | 样例 PPTX 出来，**立刻上试用机用 WPS 打开并改图表数据** |
| 2 | W3 + W4（Mac 上） | 命令行跑通全流程，含 A/D 检查 |
| 3 | W5 摸底（需试用者 10 分钟） | 确定连接器配置方式 |
| 4 | W6 | 远程在试用机安装并自检通过 |
| 5 | W5 收尾 + W7 | 试用机上 WorkBuddy 能调到确认页 |
| 6 | W8 | 试用者独立完成一次 |

每个检查点结束，在 `.agent/handoff.md` 记录状态；实现完成后写一份 Codex 审查说明交 owner 转发，审查通过后再出给试用者的包。

## 4. 风险

| 风险 | 早发现的办法 | 备选 |
|---|---|---|
| WPS 不能编辑 pptxgenjs 生成的图表数据 | 顺序 1 就上试用机验证 | 改用 python-pptx 生成图表（同样有内嵌数据表） |
| WorkBuddy 的模型不按顺序调用工具 | 顺序 5 实测 | 把流程收进更少的工具；技能说明写得更直白 |
| LibreOffice 安装对普通用户太重 | 顺序 4 记录耗时 | 试用机已有 WPS，可加 WPS 导出图片作为 B 级 |
| 未签名安装包被拦截 | 顺序 4 远程安装时观察 | 说明页写清放行步骤；正式版再评估签名证书 |
| 自定义连接器存放位置随 WorkBuddy 版本变 | 顺序 3 | 粘贴配置 |

## 5. 需要 owner 决定或配合

1. **渲染器**：首轮统一用 LibreOffice（推荐：一套代码、Mac 与 Windows 一致、授权清楚），还是在试用机上用已装的 WPS 出图（省去几百 MB 下载，但只适用于装了 WPS 的电脑）。
2. **代码签名**：首轮不签名（推荐），接受一次「仍要运行」提示。
3. **试用者时间**：需要两次桌前配合——顺序 3 约 10 分钟、顺序 6 约 30 分钟。
4. Mac 开发机安装 LibreOffice（用于本机渲染检查）。
